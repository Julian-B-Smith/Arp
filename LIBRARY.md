[L0001] Derive the terminal-path list from the parameter list, not from a prose brief | candidate | added: 2026-10-21 | tags: note-lifecycle, held-note-logic | lesson: "Every emitted note ends exactly once on every path" is only as strong as the list of paths. A prose list of paths (pattern change, chord change, switch-off, transport stop, panic) silently misses every path that a later scope choice opens: here, making ALL settings morph targets means a corner morph can switch mode, octave range, rate, latch or restart mid-note, and each switch is a new way a sounding note must end. Build the terminal-path table mechanically: one row per setting that can change while a note sounds, plus one per transport and held-set event, and make each row an M1 test with a planted control. | evidence: SPINUP-BRIEF.md "What horde needs" lists five paths; the survey's Open 5 poll (2026-10-21, DECISIONS D-000) chose "All morph", which none of the five covers; ROADMAP Phase A now requires the table. | falsifier: the Phase A spec rules that every discrete switch applies only at a step boundary after the sounding note's own gate has ended it, so no switch ever meets a sounding note (then morph adds no terminal path, only a scheduling rule). | supersedes: —

[L0002] A new output field needs its plant to fire for the right reason: carry the field through every normaliser first | candidate | added: 2026-10-22 | tags: determinism, note-lifecycle | lesson: Test harnesses usually normalise events to a fixed shape before comparing them. When the output contract gains a field (here NoteOn.stream), a normaliser that predates it silently drops it. Then a "field missing" detector fires on EVERY event: its planted control passes vacuously, and only the clean run going red reveals it. So, when adding a field: (1) add it to every normaliser and every stream or hash comparison (G1, D1), and (2) make the plant break the field on SOME events only, so the detector must examine each event rather than react to a uniform absence. A plant that fires when the field is gone everywhere proves nothing. | evidence: the S1 build on 2026-10-22. `norm()` in tools/lab_smoke.mjs had no `stream`; the plant read PASS while the clean S1 read FAIL with 88/88 untagged. Fixed by adding `stream` to `norm()` and `streamOf()`; the plant now untags only ids ≡ 3 mod 7 (DECISIONS D-009). | falsifier: harnesses that compare raw events with no normalisation, or schema-checked normalisers that fail loudly on an unknown field. | supersedes: —

[L0003] Before accepting an outside format, check our own ratified files for the property it assumes | candidate | added: 2026-10-29 | tags: determinism | lesson: A correspondent's format often states an assumption about OUR side as fact ("the lists are append-only in Arp's manifest"). Answering from the format's framing invites agreeing to something our own ratified spec already rules on differently. Before replying, grep our protected files (`spec/params.json` notes, SPEC, DECISIONS) for the property the format relies on: storage by index or name, ordering, units, ranges. Answer from what we ratified, and flag any conflict as a conflict. | evidence: horde's preset format (seq 10) stored enums by index and said our lists were append-only. Our ratified `spec/params.json` `note` says "Enums are stored by NAME." The first draft of our seq-12 reply accepted index storage for nine enums. The independent critic caught it, and the human then chose all 11 enums by name (D-040). | falsifier: a format accepted without this check that, on later review, contradicts none of our ratified lines; or ratified files that carry no such properties to check. | supersedes: —

[L0004] An absolute CPU figure needs an idle machine; an alternated old-versus-new A/B ratio does not | candidate | added: 2026-10-29 | tags: determinism | lesson: On a shared machine, absolute CPU readings move with whatever else runs, by up to about 10 % here, enough to flip a 2 % slice verdict. Do not quote one, or scale one by a guessed ratio, until it has been re-measured idle. On this Mac idle means a fresh restart, charging finished, nothing else running, and Maw's rule: 1-minute load < 1.5 and 5-minute < 2.0 (it idles near 2 with Claude open). To answer whether the code got slower, build the old commit beside the new one and alternate them in one session with `--cpu-time`. The ratio survives a busy machine even when the absolutes do not. | evidence: 2026-10-29 01:48, a busy machine: B++ with randomness read 2.08 % two-word (over the slice). The A/B against e1dbd3c read x1.016-1.020. 12:00 idle: the same load read 1.91 % (within), and the A/B read x1.015-1.02 at 48-192 kHz. The 2026-10-27 scaled estimates (1.91 % / 1.80 %) matched idle; the busy run was the outlier, which disproved the reflection that they under-read (D-041, D-042, traces/2026-10-29-cpu-remeasure-1.md and -2.md). It converges with Weir L0001 ("a cost figure from a loaded machine is only a ratio"), reached independently. | falsifier: an alternated A/B ratio that differs between a busy and an idle run by more than run-to-run noise (about 3 %), or an absolute figure that matches between busy and idle runs. | supersedes: —
